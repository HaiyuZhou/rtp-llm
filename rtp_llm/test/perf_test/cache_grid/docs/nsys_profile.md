# Nsight Systems cache replay

Run in the same container/user environment as the GPU service:

```bash
./tools/cache_perf profile \
  --result-dir /path/to/cache_grid_results \
  --cases 19314 --runs 3 \
  --profile-backend=nsys \
  --nsys-path=/usr/local/cuda-12.6/bin/nsys
```

The command adds Bazel `--run_under` automatically, using `nsys launch` with
CUDA/NVTX/OS-runtime tracing, process-tree CPU sampling and context switches.
No `.bazelrc` change or additional `--config=nsys19314` is needed. Existing
build configurations continue to apply. The nsys run-under overrides any other
run-under configuration. `--dry-run` prints the command without launching a service.

A unique session name is generated by default; `--nsys-session=case19314` sets
an explicit new session. Do not reuse an active session name. The same nsys
executable controls start/stop from inside the Bazel test process. Ensure the
installed version supports these interactive commands (`nsys launch --help`,
`nsys start --help`, `nsys stop --help`). Use `nsys status --environment` to
check CPU sampling permissions in the container.

Each replay runs `seed -> nsys start -> target request -> tail -> nsys stop`.
No Kineto `/start_profile` call is made, and service `GEN_TIMELINE_SYNC` is
disabled. The target request is unchanged and does not enable `gen_timeline`.
The capture covers the full request, including host processing and sampling,
not only model forward. `--nsys-tail-seconds` defaults to 0.1; this grace period
after the response is **not an all-rank GPU synchronization barrier**. Verify
all rank tails are present in the report. It can be increased up to 60 seconds.
No per-layer synchronization is inserted.

Reports are written to:

```text
RESULT_DIR/cache_perf_replays/profile_<id>/
  manifest.json
  nsys/cache_profile_<id>_<case_geometry>_run0.nsys-rep
  nsys/cache_profile_<id>_<case_geometry>_run1.nsys-rep
  nsys/cache_profile_<id>_<case_geometry>_run2.nsys-rep
```

The manifest records backend, session, request result, capture scope, report
paths and start/stop command output/return codes. Stop/export completes before
the next seed or service teardown. Missing/empty reports and CLI failures fail
the replay. A target exception attempts stop and preserves the original error;
cleanup failures are recorded separately. `--trace-timeout` (default 180s)
also bounds each nsys control command, including report export. After an export
timeout, inspect the recorded commands and live session before rerunning.

First capture one replay and verify that all configured GPU worker processes have
CUDA activity and CPU scheduling information. Report existence alone does not
prove all workers were captured. Existing PyTorch `record_function` ranges do
not automatically become NVTX ranges; source-level NVTX instrumentation is a
separate change. CUDA kernel names and launch correlation remain available.

Omitting `--profile-backend`, or setting it to `kineto`, retains the previous
per-rank Chrome JSON workflow. Profile results are diagnostic and must not be
mixed into formal latency measurements.
